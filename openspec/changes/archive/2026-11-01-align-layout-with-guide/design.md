# Design

## Context

동기는 proposal.md를 따른다. 현재 `_every-layout.scss`와 @use는 없으며 삭제 전 구현은 커밋 `31e744d`에서 조회할 수 있다. 그 구현에도 Stack·Cluster 프리셋은 없다. `style.scss`는 reset/base 뒤 components/pages/utilities 순서로 출력한다. `_home.scss`의 c-app과 다수 컴포넌트가 배치·외형을 함께 소유한다. `main.js:267–301,347–377`은 필터·진행 표시·목록 카드를 생성하고 c- 선택자 일부를 사용한다. app-shell의 반응형·포커스 요구사항은 변경 없이 준수해야 한다.

## Goals / Non-Goals

**Goals:** 가이드 API와 앱에서의 실제 사용을 함께 제공하고, 배치 소유자를 정적·동적 DOM 전반에서 명확히 한다. 구조 분리 후 기존 기준 화면과 상호작용을 보존한다.

**Non-Goals:** 모든 CSS 속성을 l-로 옮기거나 가이드의 일반 명칭을 전부 구현하지 않는다. 앱 상태 모델·저장소·문구·카드 기능은 변경하지 않으며, 이전 감사의 모든 스타일·접근성 지적을 일괄 수정하지 않는다.

## Decisions

### 공통 패턴과 앱 전용 배치 분리

`layout/_every-layout.scss`는 `31e744d`를 참조해 복구하고 문서화된 옵션을 추가한다. base 다음 components 이전에 로드한다. 앱 전용 배치는 `layout/_app-layout.scss`에 둔다. `.l-app`, `.l-app-header`, `.l-toolbar`, `.l-card-grid`, `.l-dialog`, `.l-toast` 등 역할 단위로 조합하고 기존 `.l-study`, `.l-all-cards`도 같은 소유 원칙을 적용한다. 범용 Stack·Cluster를 조합할 수 있는 곳은 재사용하되 기본 마진 초기화가 있는 Stack을 무차별 적용하지 않는다. 모든 외형을 범용 유틸리티로 분해하는 대안은 명확한 영역 소유를 방해하므로 채택하지 않는다.

### 책임 경계를 부모·형제 관계로 판정

외부 width/max-width, margin, 위치/inset/z-index, 부모의 grid/flex 열·행과 영역 간 gap, 자식의 외부 grow/shrink/area 배분은 l-가 담당한다. 컴포넌트의 padding·테두리·색상·타이포그래피·상태·내부 콘텐츠 정렬은 c-에 남긴다. 내부 아이콘·입력의 고유 크기, 진행 막대 폭, 카드 면의 중첩·회전, 장식 위치는 외부 배치가 아니므로 유지한다. 따라서 display/flex/position이라는 속성 이름만으로 이동하지 않는다. 예를 들어 dialog 자체의 화면 위치·가용 높이와 닫기 버튼의 패널 내부 위치는 구분한다. c-button margin 예시처럼 이 원칙에 모순되는 가이드 설명은 수정하고 허용 범위를 명시한다.

### 영역별 이전 지도

| 현재 소유 | 이전할 책임 | 유지할 표현 |
| --- | --- | --- |
| home의 c-app, app-header, view-toggle | 페이지 최대 폭·중앙 정렬·헤더 자식 배치·보기 묶음의 외부 축소 | 패딩·테두리·로고·버튼 표현과 내부 정렬 |
| toolbar, study, stats, card-grid, pagination, empty-state | 영역 사이 간격·열 수·늘이기·툴바와 통계 배치·빈 상태 외부 크기 | 카드·빈 상태·통계 자체의 외형과 내부 콘텐츠 표현 |
| card-form, grid-card footer, category-filter, card-menu | 폼 영역 외부 여백·카드 푸터 영역 배분·팝오버 기준/좌표/크기 | 폼 내부 라벨/입력 정렬·카드 내부 패딩·메뉴 상태와 외형 |
| dialog, toast | 화면 위치·외부 너비·높이 제한·스크롤 영역·외부 여백 | backdrop·전환·패널 외형·내부 버튼 표현 |

정적 HTML과 동적 생성 코드를 같은 단계에서 갱신한다. data-js/data-action, ID, ARIA 연결, dialog 요소와 이벤트 위임 계약을 보존한다. c-로 조회하는 선택자는 외형 클래스를 보존하거나 필요할 때 data-js로 명시적으로 교체한다. 새 구조를 위한 inline style은 추가하지 않고 앱 전용 규칙으로 설정한다. removed 클래스의 참조와 남은 c- 배치 속성은 사유를 확인하여 누락을 검증한다.

### 가이드 옵션과 Cover 해석

Stack small/normal/large는 0.75/1/3rem, Cluster는 0.5/1/1.5rem으로 구현한다. 옵션 생략 기본값은 각각 1.5rem/1rem이며 invalid 값은 기본 동작을 유지한다. 인라인 사용자 변수는 CSS 캐스케이드의 정상 우선순위를 따른다. 중첩 기본값과 recursive=false, push-bottom을 함께 검증한다. Cover는 기존 100vh fallback 뒤 100dvh와 자동 마진을 유지한다. 가이드의 “남은 세로 공간의 중앙”은 기하학적 중앙이 아니며 이를 명확히 설명한다. Grid로 기하학적 중앙을 강제하는 대안은 기존 계약과 콘텐츠 확장을 바꾸므로 채택하지 않는다. 일반 명칭·대표 유틸리티 목록은 참고 예시로 표시하고 HTML 코드 펜스, 유틸리티 단일 책임의 sr-only 예외와 inline 예시의 설명 범위를 정리한다.

### 검증과 완료 기준

원본 기준 임시 미리보기에서 변경 전 기준 캡처·측정값을 확보한다. 소스에서 생성한 최신 결과로 변경 후 비교하며 dist는 읽기 전용으로 유지한다. 기존 app-shell 요구사항에 따라 320px·200% 글꼴 조건의 알려진 넘침은 실제 줄바꿈/최소 크기를 조정해 해결한다. 기존 모든 기능은 회귀 대상이며 선택 버튼 hover 등 별도 외형 개선은 범위에 넣지 않는다. 패턴 fixture로 가이드의 모든 패턴과 옵션을 검사하고 root16/32에서 rem 환산을 구분한다. 앱에 사용하지 않는 패턴도 fixture로 계약을 확인한다. 브라우저가 없거나 Figma 자료를 확보하지 못하면 미검증으로 기록하고 디자인 일치로 단정하지 않는다.

## Risks / Trade-offs

- Stack 마진 초기화·변수 기본값으로 간격 변화 → 한 영역씩 이전하고 computed style·요소 크기·스크린샷 비교.
- 동적 카드만 레이아웃 누락 → 생성·수정·필터·Load More 후 생성 DOM 재검증.
- hidden이 Flex/Grid에 의해 노출되거나 dialog 포커스·스크롤 손상 → 숨김·ARIA·키보드·열린 채 분기점 전환을 검사.
- 클래스 수 증가 → 조합 가능한 공통 패턴을 우선하고 앱 전용 클래스는 역할 단위로 제한.
- 문서의 과도한 절대 규칙 → 배치 책임의 정의와 예외를 명시하며 전체 가이드를 새로 쓰지는 않음.

## Migration Plan

공통 모듈과 fixture를 먼저 구성하고 셸/학습, 전체 카드/동적 DOM, 오버레이 순서로 이전한다. 각 묶음에서 마크업과 스타일을 함께 바꾸고 기존 선언을 제거한다. 문제가 생기면 해당 묶음의 변경만 되돌릴 수 있도록 영역별 diff를 유지한다. 데이터 마이그레이션이나 배포 작업은 없다.
