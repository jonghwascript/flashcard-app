# Design

## Context

동기는 proposal.md를 따른다. `style.scss`는 base → 공통 레이아웃 → 컴포넌트 → home → utilities 순서로 로드한다. `_home.scss`의 학습 영역은 데스크톱에서 2열로 바뀌며 `_study.scss`의 액션은 태블릿부터 가로·줄바꿈 배치를 사용한다. `_every-layout.scss`에는 속성별 설명과 과거 수정 이력이 혼재한다. 실제 `mq()`는 breakpoint 맵의 px 값을 em으로 환산한 min-width 미디어 쿼리를 생성한다.

## Goals / Non-Goals

**Goals:** 최종 캐스케이드에 근거한 한국어 배치 설명과 수정 전후 동일성을 확보한다.

**Non-Goals:** 기능 수정, 스타일 정리, 미사용 코드 삭제, 블록 주석 변환, 접근성 문제 수정, 가이드 문서 변경은 하지 않는다.

## Decisions

1. 주요 배치부터 파일 단위로 정리한다. home과 공통 레이아웃을 먼저, 컴포넌트는 진입점 순으로 진행한다. 모든 선택자에 동일한 설명을 붙이는 방식은 중복을 늘리므로 사용하지 않는다. 선언 번역과 불필요한 px 환산은 줄이되 유용한 설명은 보존한다.
2. 관계·제한·전환을 레이아웃 단위당 3~5줄 이내의 `//`로 기술한다. 연결된 DOM·상태 변경·공통 규칙을 확인하고 조건을 명시한다. rem 값을 고정 px로 단정하거나 mq 이름만 보고 고정 화면 크기를 단정하지 않는다. 별도 전환이 없는 의미 있는 단위에는 이를 간결히 적되 무의미한 항목은 생략한다.
3. 검증 기준은 HEAD가 아니라 작업 시작 시점의 파일과 CSS 스냅샷이다. 사용자 미커밋 변경을 보존하고 stash·checkout으로 원본을 바꾸는 비교 방식은 사용하지 않는다. Sass `compile('src/scss/style.scss', {sourceMap: false}).css`를 수정 전후 같은 환경에서 비교한다. 결과는 메모리 또는 저장소 밖 임시 폴더에만 보관한다.
4. `//` 전용 줄과 인라인 주석을 모두 고려해 비주석 코드가 동일한지 확인한다. 문자열 내부 `//`를 무조건 삭제하는 정규식 비교는 피하고 diff도 함께 검토한다. 기존 `/* */`는 유지해 CSS 출력 동일성을 보장한다.
5. 기능 명세는 `skip_specs: true`로 생략한다. 이번 변경은 주석에만 영향을 주므로 새로운 동작 요구사항을 만들지 않는다.

## Risks / Trade-offs

- 공통 유틸리티나 스크립트 조건을 놓친 설명 → 연결 파일을 확인하고 확인되지 않은 내용은 주석에 단정하지 않는다.
- 검토 중 기능 문제 발견 → 코드로 확인된 사실·조건부 가능성·미확인 추정으로 나눠 완료 보고에 기록한다.
- 전체 빌드가 dist를 삭제함 → build/dev 대신 Sass API 검증만 수행한다.
- CSS 동일성만으로 주석의 정확성을 입증할 수 없음 → 관련 선언·DOM·상태 조건을 주석과 수동 대조한다. 브라우저를 실행하지 않았다면 렌더링 검증은 미검증으로 보고한다.
