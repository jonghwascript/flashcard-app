# Design

## Context

동기는 proposal.md를 따른다. 현재 프로젝트는 정적 HTML·jQuery·SCSS와 Gulp를 사용한다. `src/stories/Sample.stories.js`는 문자열로 Hello World를 반환하며 `autodocs`나 앱 상호작용을 제공하지 않는다. `package.json`의 `test:storybook`이 가리키는 `playwright.storybook.config.cjs`는 현재 없다. 이는 점검 후보이며 최종 판정과 중요도는 감사에서 규칙 적용 범위를 확인해 결정한다.

`doc/scss-guide.md`(삭제됨)에는 BMI Calculator 사례와 없는 `pattern.md` 링크가 있고, `layout-guide.md`는 사용자 요청으로 삭제한 `_every-layout.scss`를 실제 구현이라고 참조한다. 가이드의 모든 예시를 현 앱의 필수 구현으로 취급하면 잘못된 결론이 생긴다.

## Goals / Non-Goals

**Goals:** 규칙별 적용 근거와 실제 증거를 추적할 수 있는 리뷰 보고서를 만든다. 코드 미준수, 문서 오류, 권장 개선, 미확인 사항을 구분한다.

**Non-Goals:** 오류 수정, 레이아웃 라이브러리 복원, 테스트 인프라 구축, 외부 업로드, 배포, 가이드 자체 개정은 포함하지 않는다. vendor jQuery는 외부 의존성으로 연결·버전·사용 경계만 확인하며 라이브러리 내부 코딩 스타일은 현 프로젝트 규칙 적용 대상에서 제외한다.

## Decisions

1. **규칙의 적용 여부부터 기록한다.** 13개 문서를 개발 규칙, 접근성 체크리스트, 참고 대응표, 작업 프롬프트, 프로젝트 기록으로 분류한다. 비어 있는 문서는 기준 없음으로 기록한다. 일반 지침과 프로젝트별 사례를 구분하고 AGENTS.md·사용자의 최근 결정·가이드의 명시된 우선순위를 반영한다. 충돌은 원문과 실제 소스를 함께 제시한다. 모든 문장을 무조건 준수 검사로 바꾸는 방식은 사용하지 않는다.
2. **현황 표와 발견 목록을 함께 제공한다.** 규칙 표는 준수·미준수·판단 보류·해당 없음과 이유를, 검증 표는 검증 완료·미검증·해당 없음을 기록한다. 발견에는 중요도, 가이드 경로·절, 소스 위치, 재현 조건 또는 코드 근거, 사용자 영향과 개선 방향을 포함한다. 정적 위험 가능성을 실제 브라우저 실패나 WCAG 위반으로 단정하지 않는다.
3. **소스 전체를 계층별로 점검한다.** HTML과 JS가 생성한 DOM, 상태 전환, 모든 버튼·링크, SCSS 선택자·변수·자산 경로를 연결한다. 선언 순서·토큰 중복·미사용 코드 등 유지보수 규칙은 기능 결함과 분리한다. 최근 px 주석 형식과 미사용 layout 삭제는 승인된 기준으로 보존한다.
4. **원본에서 임시 미리보기를 만든다.** Gulp clean이 dist를 삭제하므로 build/dev는 실행하지 않는다. 임시 폴더에 HTML, Sass 컴파일 CSS, JS·이미지·폰트와 `src/data.json`을 포함해 배치한다. include 사용 여부를 먼저 확인하고 필요하면 file-include 처리를 임시 출력에만 적용한다. JS 문법 검사와 Sass 컴파일 결과를 기록한다. Storybook 검사는 실제 명령과 설정이 유효한지 먼저 읽고 저장소 밖 출력이 가능한 검사만 실행한다.
5. **브라우저 검증을 정적 검토와 분리한다.** 설치된 Chrome·Firefox만 사용하고 Chromium 대체 사용 시 제품명을 정확히 적는다. 320·375·767·768·1023·1024·1440px, 가로 667×375, 텍스트 200% 조건을 확인한다. 보기 전환, 카드 뒤집기·학습 상태, 카테고리·숙련 필터·셔플, 생성·편집·삭제·오류·빈 상태·추가 로딩·토스트를 해당 데이터로 재현한다. 각 컨트롤의 hover·포커스·실행·열림·숨김·포커스 복원을 확인하고 reduced-motion·고대비는 가능한 도구 범위와 한계를 적는다.
6. **Figma 일치 여부는 증거가 있을 때만 판정한다.** README·로컬 디자인 자료·기존 기록의 근거를 확인한다. 필요한 디자인이나 연결을 확보하지 못하면 해당 시각 비교와 과거 MCP 호출 순서 준수는 미검증으로 보고한다. 현재 코드만으로 과거 작업 절차를 입증하지 않는다.

## Risks / Trade-offs

- 가이드가 낡아 정상 소스를 위반으로 오판할 위험 → 문서 오류를 별도 목록에 기록하고 삭제된 미사용 스타일 복원을 요구하지 않는다.
- 브라우저·스크린 리더·디자인 자산이 없어 검증이 제한됨 → 독립적인 정적 검토는 완료하고 미검증 사유와 후속 검증 조건을 적는다.
- 앱의 저장 데이터가 검증에 오염됨 → 임시 서버와 분리된 브라우저 컨텍스트·테스트 데이터만 사용한다.
- 검토가 자동 수정으로 확장됨 → 보고서만 작성하고 소스·설정·기존 문서의 diff가 늘지 않았는지 최종 확인한다.
